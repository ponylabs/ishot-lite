# 保持翻译忠实且可维护

仅在用户明确按名称调用 `seek-translate-docs` 时执行本扩展工作流。其他 Skill 不得自行选择或加载它，也不因推测的翻译需要启动。普通文档修改按项目已确认的最小同步规则处理，不能仅凭推测的翻译需要扩大范围；没有授权依据时先询问。

先确认项目是否已有语言对应、术语、生成文件和一致性规则。没有规则时以任务指定源语言为准，只翻译要求范围，不创建额外翻译系统。冻结历史与生成文件遵守所属策略。

## 按改动类型工作

已有对应文档的小改动，读取最后一致版本、本次源差异和现有译文，只修改受影响语义单元，保留已审阅的其他表达。两侧同时修改或段落无法对齐时人工协调，不能强制覆盖任一侧。

扩展流程中的散文增量和整篇新译文交由独立翻译 Agent 执行，传入最小完整的源差异、现有译文、项目术语与同步规则。新译文先读术语和同类样例，再按段理解后自然表达，不机械逐句搬运。宿主无法委派时说明限制，不声称已完成独立翻译流程。重命名/删除时检查对应文件、索引和已有一致性元数据，执行仍遵守授权范围。

如果项目已有可靠的差异简报或机械同步工具，可以使用：纯共享代码块变化可机械同步，散文变化仍需语义检查。不得凭空调用上游专用脚本，也不能因检查器通过就认定意思相同。

## 三遍检查

1. 表达：按目标语言写成自然技术文档，保留结构和命题。
2. 忠实：逐条对照条件、否定、程度、义务、例外和事实，确认没有新增或漏掉；术语遵循项目表。
3. 独立阅读：不看源文读译文，修复只能靠源句才能理解的生硬表达。

命令、标识符和代码块默认保持原样，除非项目明确允许翻译注释。文档链接保持语义目标与 fragment/query；已有本地化对应时遵循项目规则，不存在时不能伪造路径。未确定术语说明歧义并列为待定，不能随意创造多个译法。

## 完成

检查标题层级、列表顺序、表格行列、链接和代码，再核对机器检查覆盖不到的含义与语气。只在人工确认一致后更新已有一致性记录，范围限于本次确实确认的文件，不能批量重写记录掩盖漂移。

报告新增与增量更新的文件、执行的检查及待定术语。审阅确定术语变化时更新其唯一术语来源及受影响用法，而不是只补某一篇。
