# 精炼工程表达

先写足以正确使用和维护的规则，再去掉推演过程、重复和装饰。这里的契约是调用者、实现者、生产者或消费者依赖的义务、不变量、前后置条件及兼容承诺。本 Skill 负责表达判断与必要内容覆盖；放置位置、文档分层和维护流程使用 [seek-doc](../seek-doc/SKILL.md)。这是判断指引，不是穷尽检查表。

## 输入、范围和权限

- 必须有明确范围：具体文件、模块、给定差异或明确指定的全仓。任务未给出且上下文不能唯一确定时，指出缺少范围并停止扫描，不默认全仓，不展开访谈。
- 支持 `automatic` 和 `interactive`；默认自动，仅用户明确要求提问或校准时使用交互。模式只决定是否提问，不授予写权限。审阅、审计只报告；明确要求编写、修复或精简时才修改。
- 确认当前分支、比较基线和适用的 `AGENTS.md`；不查看无关分支，不覆盖用户改动。
- 排除第三方依赖、供应商目录和归档快照；不通过符号链接重新进入排除目录。按仓库实际目录设置排除项，并放在包含规则之后；例如搜索以 `--glob '!vendor/**'` 收尾，Git 使用 `:(exclude)vendor/**`。只剩排除对象时报告无适用文件。冻结的历史记录仅可为核实具体引用读取，不现代化其措辞或链接。
- 生成目录、快照和测试样本不是普通文稿。追踪文字的源头及每个消费者，先改拥有者，再按现有流程更新派生物。生成器只抽取首句时，首句必须独立保留输出端所需含义。
- 项目有多语言文档时，按实际来源和同步约定更新另一版本，不假定某语言永久拥有内容，不引入固定双语要求。

## 保留完整含义

编辑前逐项找出执行者和动作，条件、时机与顺序，必须/可以/禁止，否定保证与例外，所有权、副作用、失败及后果。删除修饰或叙述后，这些有效事实必须仍成立。少几个字本身不是改进。

使用点必须保留读者当场需要的行为、失败、责任与后果。架构、算法、长篇原因、历史和扩展示例链接到唯一归属；链接不能替代必要的本地约束。删掉原因会诱发误用或错误简化时，保留短原因，否则说明后果并链接详细解释。

“契约、边界、形态、表面、关卡”等词不是禁用词，但先判断准确的规则、字段、类型、时机、模块职责或失败条件是否更清楚。保留真实技术含义、可搜索的机制名，以及影响行为的情态、时序和否定强调；仅移除装饰性强调。中文自然表达，命令、路径和 API 标识保持准确。

## 执行流程

1. 确认范围、模式、权限和基线，读取适用约束以及拥有该段文字的代码或文档。
2. 按[内容覆盖](references/coverage.md)查缺，不只找长文件。搜索和字数仅用于发现候选，不能自动判定冗余。
3. 对每处选择保留、补充、精简、恢复、重组或暂缓；使用[对照示例](references/examples.md)校准，不为了完成删除指标制造改动。
4. 有修改授权时应用明确改动；先改源头，再更新派生物。发现新的通用原则后，检查范围内同类段落。
5. 提示词、模型可见文本、界面及诊断字符串按行为变更处理，遵守拥有者场景验证；不能把它们悄悄混入纯文字润色。
6. 运行相关文档检查、实际行为检查和 `git diff --check`，核对差异没有排除目录或越界改动。搜索曾意外命中排除对象时如实说明，不声称全过程排除成功。
7. 报告检查范围、明确改动、刻意保留、暂缓项，以及实际运行和未运行的检查。结构通过不等于语义完整。

## 有分歧时

只有至少两种版本都保留全部事实、却在合理原则间存在取舍，且现有规则未解决时，才算边界案例。删掉关键事实的版本不是备选。

自动模式中完成已授权的明确改动，报告真正的边界案例，不为前进而削弱含义。交互模式把同类问题按原则分组，给出两三种有效版本、推荐项和事实或结构差异，不用劣质选项陪衬。在获准的 PR 行内校准中，可把推荐临时版本放入差异，把备选附于对应行；请求交互本身不授权发布评论。

用户决策后，仅在授权维护本规则时把可复用原则和示例提炼进示例文档，不记录审阅对话或 PR 过程；再用于当前范围内同类段落。

## 专项工作

明确清理会话或评审过程残留时，使用独立的 [过程残留清理](../seek-trim-cot-leakage/SKILL.md)，不把有效理由、例外和历史当作冗余删除。
