# 各类文字需要覆盖什么

这不是单向删减。代码、类型或结构没有表达必要规则时，应补充或恢复；局部已经显而易见时不添加重复注释。

| 位置 | 必须判断是否需要说明 | 避免 |
| --- | --- | --- |
| 公共 API 注释 | 返回值差别、抛出或异步失败、副作用、资源责任、时序、取消、持久性 | 逐行复述内部状态机 |
| 内部注释 | 非局部关系、复杂结构、不变量、竞态顺序、所有权、安全隔离、意外失败 | 解说显然的分支和循环 |
| 模块说明 | 模块角色、依赖、责任和非显然设计选择，链接设计依据 | 逐一预告下方函数 |
| 测试 | 不直观的样本或断言原因、平台适配、真实入口、间接观察为什么必要 | 测试步骤旁白和文件清单 |
| 操作指南 | 前提、必要动作、真实入口、可观察结果和简短风险提醒 | 只有“运行测试”而没有观察标准 |
| README | 配置、语义、失败、限制、扩展点，存在时包含模型可见影响 | 日常清理清单、另一模块的完整定义 |
| 已实现设计记录 | 独有原因、机制、备选、后果、交付验证证据和明确覆盖缺口 | 仍用未来时描述现状；把验证证据当过期任务删掉 |
| 事故复盘 | 事件顺序、证据、因果链、影响和预防 | 重复说服或不能证明因果的实现细节 |
| Skill / Agent 指引 | 改变行为的规则、明确适用范围和局限，链接事实来源 | 把示例当穷尽清单、复述通用能力 |
| 示例 / 配置注释 | 权限限制、非显然接线或加载顺序、安全取舍、重放语义、例外和易误用处 | 配置树已表达的排列和目录 |
| 诊断 | 失败对象或路径、违反的规则，以及不明显的修正方法 | 内部执行旁白或含糊的“失败了” |

## 可见文字是行为

提示词、工具描述、错误文本及模型结果会影响 Agent 决策；用户界面文案会影响操作和可访问性。编辑前找拥有者、消费位置、实际场景和现有证据方式。文本、无障碍名称、提示、占位符和格式模板一起检查，参数和插值含义不能改变。

- 项目已有本地化字典或类型化文案入口时沿用，不绕开它硬编码。英文用项目的大小写规则；没有特殊规则时使用句首大写并保留专有名词。中文按中文习惯，不机械照搬英文。
- 更新拥有文字的可运行场景及项目实际要求的快照、交互或界面证据；快照更新必须审阅变化原因，不能为通过检查照单全收。
- 范围内没有拥有者场景、权限不足或关键证据不可得时，保持原文并报告暂缓；不能用“只是润色”绕过验证。经授权扩大范围后才补场景再改。
- README 可引用本模块拥有的稳定模型可见文字；完整生成目录、另一模块 schema 和消费端文案链接到拥有者。本地只写本模块条件或差异。

## 约束、原因与历史

限制如果改变使用或安全维护方式，就是必要事实，例如配置按进程缓存导致修改后必须重启。普通私有函数清理不属于使用契约。已实现记录可移除执行清单，保留证明决策的验证层次、真实入口和已知缺口；冻结归档不在本 Skill 的改写范围。
