# 变更与证据矩阵

矩阵用来选择证据，不强制固定目录、语言、测试框架或覆盖率。先读当前项目真实配置，再选择命令；新增能力尚未实现时报告计划而非验证完成。

| 变更面 | 必要判断与证据 | 常见假通过 |
| --- | --- | --- |
| 函数或模块行为 | 正常、边界、错误断言；缺陷尽可能先红后绿 | 只断言函数返回了对象 |
| 公共接口/共享类型 | 追踪生产者与所有当前消费者，参数、结果、异常、取消与兼容性 | 仅测试生产者内部方法 |
| 构建、包导出、依赖、启动入口 | 真实构建、导出/依赖一致性、产物冒烟 | 从源码启动成功但发布包缺文件 |
| 配置与默认值 | 跟踪配置优先级和权威读取点，观察最终生效值 | CLI 接受参数但后续被覆盖 |
| 数据写入/迁移 | 隔离数据、部分失败、重复提交、兼容和恢复；跨版本分别验证新读旧与旧读新或安全拒绝 | SQL 语法检查或单向可读被当成迁移安全 |
| 多阶段失败路径 | 沿实际入口核对处理顺序和状态责任，针对受影响的输入与序列化、存储、报告等交互运行失败样本 | 每个组件各自通过，被当成组合行为已经验证 |
| UI/CLI/提示词/工具输出 | 使用实际入口，核对可见输出与关键行为；必要时快照/交互证据 | Markdown 检查代替行为验证 |
| 文档/注释 | 事实来源、精确例子、链接及内容审查；标明平台范围 | Linux 一次通过被写成全平台 |
| 外部服务 | 获授权且凭据可用时的真实边界测试，秘密不输出 | mock 通过被写成服务可用 |
| 检查器与验收规则 | 有效样本通过、故意无效样本通过真实 runner 失败 | 只检查错误消息字符串存在 |
| 异步、并发和资源 | 确定性同步、清理完成、必要的跨进程隔离 | sleep 后成功或多跑一次成功 |

## 测试选择的核验

参数转发取决于当前命令工具，不能照抄另一包管理器语法。查看 runner 报告确认预期用例确实运行。静态依赖选择通常看不到配置加载、子进程、插件、构建产物和外部服务，要额外选对应入口。

测试过滤只决定跑哪些用例，覆盖范围决定测量哪些源码；不能为了绿色结果排除仍受影响的文件。覆盖率达标不证明断言正确，缺失测试不得用“允许无测试”选项掩盖。

## 平台与构建前置条件

先完成检查依赖的生成步骤，再诊断类型或 lint 错误；陈旧声明文件或本地缓存可能掩盖干净环境失败。只能宣称已运行平台的结果，平台无法执行时指出缺口并使用项目实际 CI 证据，不借另一平台成功推定。

新门禁至少用一次负例确认实际命令返回失败；业务检查与模板自检应分别描述，不能让其中一项替代另一项。
