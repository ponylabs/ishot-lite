# 提交前验证

按当前版本和实际变化选择最小充分证据，不机械运行全仓，也不把局部通过描述为整体通过。具体命令归项目配置、README 和适用规则所有，本 Skill 不维护第二份命令副本。

## 确认基线

1. 确认 checkout、仓库根、分支和工作区状态。分开查看已提交、暂存、未暂存和未跟踪文件，避免只检查 `HEAD` 漏掉待交付内容。
2. 需要 PR 或分支审查时，核实当前远端 base 和精确 head；在获准的网络访问范围 fetch。不能猜测主分支或沿用已重定向的 PR 基线。
3. 用已验证的 base/head 确定完整差异；工作区各层另列。初始提交无父节点时明确使用空树或全文件范围。合并、变基或基线改变后重建范围。
4. 如果无法确认基线，说明限制；可以验证当前工作区，但不能声称已覆盖全部 PR 差异。

## 选择证据

读取 [变更与证据矩阵](references/evidence-matrix.md)。每个行为变更至少有能捕捉对应回归的证据；共享接口变化追踪消费者，动态配置和构建入口不能只靠静态依赖图选测试。

资源或异步测试先应用 [测试可靠性](../seek-test-reliability/SKILL.md)。覆盖率选择与测试选择是两回事；不得删掉受影响范围、降低阈值或允许零测试来隐藏缺口。核对实际选中数量、跳过项和断言目标。

## 执行与证据失效

先运行最窄有效检查，变化确实跨边界、调查 CI 或用户要求时扩大。已通过且内容、依赖及环境未改变的证据不必重复运行。

测试后代码、生成物、依赖、钩子自动修复或合并结果改变时，重新评估受影响证据。检查输出不得只凭退出码：确认没有零测试、误过滤、跳过全部、陈旧构建产物或替代环境冒充。

## 失败处理

相关检查失败，先修复并复验或报告阻塞，不先推送期待 CI 碰巧不同。只读任务不授权修复；权限、密钥或外部条件缺失时保留未运行事实。不能把未经证实的失败归为环境问题。

记录精确命令、测试/步骤、错误及环境；区分产品行为、测试实现、平台差异和基础设施。不要吞异常、削弱断言或绕过钩子。需要例外时按用户明确授权和项目制度处理，交付仍必须说明缺口，例外不等于通过。

## 提交与远端

仅在已有授权下提交和推送；按项目要求采用中文说明。先检查最终 diff、秘密及无关文件，提交钩子若改文件须检查并复验。

普通推送使用正常快进；历史重写需单独明确授权，并记录刚读取的远端 OID，使用精确 lease 拒绝并发覆盖，禁止裸 force。不要迁入任何上游先推送后验证的工具专用例外。

推送后重新获取并核实远端 ref 与预期提交一致，再查看该精确提交的 CI。pending、skipped、failed、没有运行都不是 success。无工作流结果时调查触发事件、过滤、权限及 PR 冲突等事实，不用空提交或反复切状态制造运行。修正已授权范围内失败后重新验证。

## 完成报告

列明实际检查、对应范围、结果、未覆盖和阻塞；本地与远端分开，机器检查与内容审查分开。只有精确最终版本的证据支持时才声称通过。发布或部署是独立动作，不由推送成功自动授权。

## 独立专项

性能调查、PR 说明与依赖栈操作分别由独立 Skill 处理，不由本 Skill 统管开发流程。按实际变化选择已有证据；这些专项不会仅因提交前验证而全部触发。
