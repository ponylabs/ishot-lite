# 维护 Agent Notes

减少活跃记录的维护负担，但不丢失仍能指导工作的理由。先读 [Notes 规范](../../notes/README.md)、[归档规则](../../notes/archived/AGENTS.md) 和目标状态的局部 AGENTS；本 Skill 管执行方法，不另设一份状态或格式规范。

## 新增时检查取代

先确认已有记录不能满足需求。搜索活跃记录中同一决定、机制和被拒绝的替代方案，结合当前实现、配置、文档和入链判断完整或部分取代。新记录同次处理已知取代关系，不能把已知匹配推迟到未来全库审计。部分取代保持活跃并互链；完整合并须遵守规范中的知识保留条件。

## 按未来价值分类

- 已实现且仅为小型 UI 或纯机械记录：按授权删除并修复入链。局部 bug、性能、能力或行为决定不能仅因实现小就删除。
- 已实现且仍有理由、替代、负向保证、持久/传输语义、所有权、安全或重引入条件价值：保持活跃。
- 已实现、完整交付、不再指导未来但仍有历史价值：归档。
- 未实现提案：继续活跃；不再值得推进时拒绝，不能归档。
- 已拒绝：仅在仍能避免有吸引力的真实错误时保留，否则按授权删除并修复入链。

不以年龄、字数或配额决定结果。范围内逐篇核实，类似情况采用一致原则；有争议先保留并说明。

## 归档操作

1. 移动前运行普通检查，确认当前活跃记录符合格式；结合实现确认决定已完整交付并符合归档条件。再将 implemented 中的记录移到 archived 的同类别，保留首次提出日期和原文件名。
2. 只在 `Status: implemented` 下加入 `Archived: YYYY-MM-DD`；不重写、翻译或格式化正文，不修复历史出链。
3. 检查活跃入链：改指当前权威说明，或在明确引用历史时改指归档路径，或删除无用引用。
4. 运行 `python3 scripts/check_harness.py --seal-archives`。该模式先确认旧封存未变，再追加新文件哈希；失败时不得重置 manifest 或扩大例外。
5. 运行普通检查及 `python3 -m unittest discover -s tests -v`、`git diff --check`；按变更选择其他实际验证。

封存后不得再修改、移动或删除记录。本单语言模板不伪称检查了上游双语一致性。

## 验证与交付

机械检查之外，核对理由、替代、取代关系和当前事实；格式通过不证明这些内容真实。报告保留、更新、拒绝、删除或归档的记录及理由，说明有争议的判断。不能宣称归档出链仍有效，因为它们不按当前状态检查。
