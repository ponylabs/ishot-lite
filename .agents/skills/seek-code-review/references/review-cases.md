# 审查案例与边界

## 接口两端

前端传入过滤条件，后端 schema 接受但处理器忽略。类型检查和内部函数测试都可能通过；审查应跟踪请求实际入口到查询结果，加入带不同过滤值的行为断言。

## 约束绕过

UI 禁用危险操作，但直接 API 仍执行；工具 schema 限制参数，但内部调用者传入任意值。把约束放在执行责任边界，并用直接及替代入口负例验证，而不是新增一段提示词。

## 共享与派生状态

模块缓存借来的可变对象，外部更新后 UI 与数据库不同步。先确定谁拥有数据、何时视为成功、哪些消费者需要通知；不要简单复制多份状态或在多个位置补条件。

## 输出上限

仅截断正文到字节上限后又追加 JSON 包装和元数据，最终仍超限。验证完整输出所有者，覆盖中文等多字节字符、空预算、精确预算和单个超大项。

## 真实入口

源码导入测试通过，但构建包导出或启动脚本错误。需要从实际交付产物的入口冒烟；不要把测试手工装配成永远绕过入口的结构。

## 验证反例

“日志包含成功”不是数据库提交成功；“调用了 close”不是资源已关闭；“模型说做了”不是文件发生变化。选择外部可观察的结果与清理完成信号，说明测试不能覆盖的外部条件。
