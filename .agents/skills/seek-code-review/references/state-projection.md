# 可恢复状态投影

仅用于已有日志派生状态的设计，不要求所有项目采用事件溯源，也不把普通备份恢复或异步加载改造成投影。先找状态所有者、实际读写入口、恢复时点和同步 API 约束。

## 事实与运行时分离

在既有投影体系内，派生业务事实由明确投影维护，外部资源、注册句柄、Promise 和进程所有权留在运行时。消费者使用所有服务的领域方法，不直接拿投影定义或注册句柄。必需依赖必须显式声明，不能用另一条恢复路径掩盖缺失。

纯 reducer/重放计算保持确定性，不执行 I/O、发起模型/工具调用或触发运行时副作用；数据获取和运行时动作放在显式所有者中。只有项目已有同步 API 契约时，初始化、事件应用和读取才须同步，异步准备与恢复按项目契约处理，不能擅自改成同步。引用相等性只有被消费者用于通知或缓存判断时才构成契约：无关事件和值不变时保持相应稳定性，不要求所有实现使用同一对象身份。纯读取回调不偷偷接管缓存、注册或副作用。

## 版本与容量

持久化格式应通过项目自己的 schema；检查点恢复加后缀重放必须等价于完整重放。状态字段或恢复含义变动时按现有协议改变版本，明确水位边界，避免漏应用或重复应用。

优先固定或次线性状态。必要的线性状态应有当前消费者和明确内存、重放、单事件成本，不能习惯性保存全量历史索引。也不能为省内存丢掉同步消费者真正需要的当前值。

缓存必须可丢弃重建而不改变行为。只有序号不够支撑同步读取载荷时，存储必要当前值或提供明确异步准备阶段，不能在 getter 或缓存缺失中暗读全历史。删除已被替代的恢复规则，避免两套逻辑漂移。

## 就绪和生命周期

注册完成与对象历史恢复完成是两种就绪状态。必需注册失败应阻止对应激活；加载所有者完成恢复后才能把对象交给同步读者。期间可能到来的事件要根据实际机制防丢，不机械移动监听器或在不支持异步的回调里等待。

同步 API 不能用 Promise 冒充。迁移前列出真实公开消费者，新的必需依赖或激活步骤要同步迁移调用方；有外部兼容影响时使用 [升级指南参考](../../seek-create-upgrade-guide/SKILL.md)。

## 验证

通过真实加载和存储生命周期覆盖：有效、缺失及不兼容检查点；后缀与完整重放等价；无运行时副作用；延迟注册、注册失败、替换、等待期间释放。比较值、通知、错误归属和时序，不把原本只影响一个读者的错误移成全局启动失败。用可控屏障，不靠微任务次数证明时序。
