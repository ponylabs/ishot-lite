# 失败场景与安全后续

| 场景 | 错误处理 | 应确认的事实 |
| --- | --- | --- |
| 数据写入成功，响应超时 | 未核实就重试导致重复写入 | 是否有事务标识、幂等键或可查询结果；结果未知先核实 |
| 多步导入一半失败 | catch 后返回“导入完成” | 已提交范围、剩余状态、补偿是否真正成功 |
| 后台任务失败 | 只写不可见日志却仍显示正常 | 状态所有者、降级显示、停止或恢复责任 |
| 取消后释放资源 | 请求取消即释放仍被使用的连接 | 工作是否静止、谁等待结束、清理顺序 |
| 报错服务自身失效 | 再调用同一服务报告错误 | 独立可用的后备输出及敏感信息过滤 |
| 非法或极端输入与记录/序列化同时发生 | 单测只验证业务拒绝，实际入口却先记录输入并在另一边界中断 | 校验与副作用的真实顺序、是否已有部分提交、继续执行的前提及最终报告；诊断或持久化失败可以中止，但须符合其所有者的明确契约 |

例外也需要依据：外部服务明确允许的瞬时重试可以保留，但预算、取消、重复副作用和最终失败报告必须完整。不要将第三方政策套到本地确定性测试或所有业务操作。
