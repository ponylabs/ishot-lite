# 初始化的验证交接

模板检查只证明模板结构，不能证明派生业务正确。交接时从已有配置确认下列事实，记录在项目已有的验证说明或交付摘要，不额外建立重复清单。

## 覆盖映射

| 实际变化 | 最少需要的证据 | 不足以替代的证据 |
| --- | --- | --- |
| 业务函数与规则 | 正常、边界和拒绝路径的行为断言 | Markdown 链接通过 |
| API 与消费者 | 请求到实际处理入口，并核对消费者契约 | 仅单独调用内部函数 |
| 数据库结构或写入 | 隔离数据上的约束、迁移和失败状态 | 只检查 SQL 能解析 |
| 应用构建或入口 | 实际构建产物的启动或冒烟 | 源码测试通过 |
| 文档和 Skill | 结构检查及内容/实际 Agent 场景 | 文件存在或格式合法 |

只对当前项目实际涉及的行建立验证。计划能力不需要提前建空测试，但应明确实现时的验收要求。

## 三方核对

1. 查 README 和适用 AGENTS 中声明的命令。
2. 查包管理器/构建配置及本地脚本实际选择的测试、失败退出码和环境。
3. 查现有 CI 的触发事件、工作目录、运行环境、步骤和过滤规则，确认不是只跑模板自身测试。
4. 安全临时副本中加入一个可控失败，使用真实验证入口观察非零结果；恢复后通过。只验证命令时不要声称远端 CI 已运行。
5. 推送获授权后，核实精确提交的工作流及结果；缺少运行要调查触发/权限/冲突等原因，不把空结果当成功。

## 负例

派生 JS 工具增加 `node --test`，但 CI 仍仅运行 Python 的 Harness 单元测试。即使两项 Python 命令通过，业务失败仍可被漏掉。修正是将真实业务测试接入该项目的验证链，并保持模板检查的有限职责，而不是删除业务失败测试或把 README 改回模板命令。

平台分支保护、凭据及生产连接不随克隆自动生效；不在无授权时更改权限。无 CI 的小项目可以报告真实本地证据，不必为满足模板而创建虚假的远端门禁。
