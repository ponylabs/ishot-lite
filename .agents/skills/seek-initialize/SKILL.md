# 初始化派生项目

初始化是一次有完成条件的交接，不是填满模板，也不表示已实现整个业务。已有项目优先增量接入，重复调用不得重置已确认的选择。

## 确认起点

1. 检查仓库、分支、已有内容和用户修改，确认任务是派生新项目而非维护模板本身。
2. 提取目标、非目标、交付形态、环境、数据和权限约束。仅询问影响当前决策的缺失信息；不从模板推断业务技术栈。
3. 提出满足首个目标的最小结构、模块边界和验证方式。代码、部署和外部服务操作仍需在当前授权范围内进行。

## 建立真实知识

保留六个固定文档，按 [文档契约](../../../docs/AGENTS.md) 初始化：README 写用途和入口，architecture 写实际模块与边界，development 写已确认环境和流程，testing 写真实命令、覆盖与缺口；AGENTS 写适用约束与路由，docs/AGENTS 保留类型与名称契约。没有业务实现时明确当前为空及首个目标，不虚构事实。条件文档仅在对应场景成立时创建。

- 原位改写根 README 为真实项目用途、当前状态、实际入口和运行验证方法。未实现、未验证与待定必须分开。
- 根 AGENTS 保留全局底线和按需 Skill 路由，更新项目入口及验证指引。存在长期局部约束才创建子 AGENTS；模块形成独立职责才补模块 README。
- 项目命令从实际配置和执行结果确认，不直接复制模板命令当业务验收。
- 中途暂停时，将已确认选择、缺失条件及下一步保存到项目可发现的现有事实或任务位置，并从入口可达；不要只在聊天里说明。

## 交接验证链

逐项检查现有本地脚本、测试配置、Git 钩子和 CI 工作流，而不只修改 README。对每项决定保留、扩展、替换或移除，并确认它覆盖什么。

按 [验证交接清单](references/verification-handoff.md) 执行：README 的验证指引、本地命令及实际 CI 必须描述一致的覆盖范围。新项目使用 Node、Go 或其他栈时，不能保留只跑 Python 模板测试的 CI 后宣称业务已验证。没有 CI 或暂不能配置时，明确本地已验证范围和远端缺口，不虚构强制门禁。

若已实现首个行为，建立能观察该行为的测试，实际证明失败用例被同一入口拒绝、修复后通过。尚无业务代码时可以完成知识初始化，但只能报告基础结构已验证，不能声称项目功能或业务 CI 已就绪。

## 初始化退场

1. 删除根入口中仅用于首次初始化的触发提示和占位内容；普通任务不再重新询问初始化问题。
2. 通用初始化 Skill 可保留供用户明确再次调用。模板自身设计和验证说明在派生项目中删除或改写，检查面向当前项目的称谓和事实归属，修复相关入链；来源、许可和可复用 Skill 中确有用途的模板背景保留；不要批量删除未知用户文件。
3. 保留通用脚本时，确认扫描范围、依赖和运行环境仍适合真实项目；项目专属检查须独立接入。
4. 通过真实检查并审阅最终差异。测试后变更文件需要重新评估受影响证据。

## 完成条件

入口描述真实项目，当前目标与下一步明确，必要选择可跨会话恢复；初始化提示已退场；验证链的已执行、失败、未配置范围明确。用一次新的普通任务检查没有重新初始化；跨会话行为只有实际换上下文验证后才可声称通过。
