# 可追溯的界面演示

记录与发布是两个步骤。先生成本地证据；只有任务明确包含发布时才上传或改 PR。不要强制所有项目生成 GIF、调用真实付费模型或使用某个上传工具。

## 真实来源

为目标变更准备干净工作区，记录精确提交、构建方式、服务地址、运行模式和必要的模拟边界。使用该代码启动的真实应用路径，不能把其他分支的构建归因给目标 PR。用户要求真实服务时不可静默换成 fixture；密钥缺失则说明阻塞，不读取或展示秘密值。

一个故事来自一次隔离运行：独立临时数据根、工作区、会话以及浏览器上下文。不能清除用户原浏览器状态以伪造隔离；确有共享状态就注明。失败采集只用于诊断，重录应重新开始，不能拼接不同运行伪造完整流程。结束进程用确切 PID，避免宽泛 kill 误伤其他工作。

## 采集与编码

选少量有意义状态，使用唯一语义定位器和真实完成条件。固定等待可用于阅读停留，不能证明准备完成；完成文本不能误匹配输入回显。演示失败、取消或恢复时展示错误/状态以及后续结果，不只录按钮被点击。

固定视口和采集尺寸。连续视频保留中间动画；仅有截图时说明是状态串联，不声称连续交互速度。关闭录制上下文并确认视频刷盘后再编码。只用已有允许的工具，缺依赖时报告，不擅自安装。

裁剪保留同一源的连续因果区间；加速、间隔和停留要披露，不能拿加速 GIF 当响应时间证据。保持文字可读，必要时按同次运行的连续区间拆分并注明顺序。禁止合成缺失状态。原始素材和临时证据放在明确忽略的位置，默认不把大媒体提交进 git 历史。

## 审核和交付

检查最终编码产物本身的顺序、尺寸、时长、帧数、末帧停留和大小。若查看器只显示首帧，解码代表帧检查；原图不能证明最终调色板和编码正确。完整检查选定区间，排除凭证、私人数据、其他标签页和通知。

交付注明提交、构建来源、真实/模拟边界、运行模式、截图或视频，以及速度/区间调整。发布前重新读取目标 head，与示范提交比较；已变化则重录或明确取得使用历史示范的授权，不能暗示仍代表当前版本。

使用实际支持且获授权的附件通道，保留原正文。上传后读回正文、检查链接可访问和资源类型，再复核 head。附件上传失败不等于发布完成，也不能换资产分支绕过限制；保留本地验证产物并报告可恢复的阻塞。
