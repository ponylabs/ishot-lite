# 偶发 CI 失败诊断

只读诊断不自动授权修改、重跑工作流或更改配置。先保存事实，再决定是否存在可实施的修复。

## 固定证据

记录仓库、workflow/job、精确 SHA、runner、时间、失败命令/用例和稳定错误特征。把 checkout、下载、磁盘等基础设施输出与测试输出分开。

比较失败与成功运行，优先同一 SHA；否则确认相关测试和配置一致。一次重跑通过不能证明基础设施故障，一次超时也不能证明产品竞态。日志可证明共享主机资源重叠时保留运行链接；拿不到主机指标就明确限制。

## 从证据分类

- 主机资源碰撞：独立进程争用同端口、路径、缓存或数据库命名空间。
- 生命周期不完整：清理返回后子进程、服务或回调继续输出或写状态。
- 全局污染：顺序依赖环境、cwd、mock、时钟或模块注册状态。
- 负载敏感同步：sleep 或假定事件循环轮次替代就绪/结束信号。
- 平台或入口差异：错误随系统、shell、文件语义、源码/构建模式变化。
- 产品并发缺陷：测试资源已隔离，显式重叠仍稳定暴露真实行为竞态。
- 外部瞬时失败：证据符合该服务明确的重试政策。
- runner 基础设施：独立于测试命令的直接失败证据，不靠猜测归因。

多项独立事实分别报告，不能把 timeout、signal、退出码和断言合并成一个未经证实的结论。

## 最小复现拓扑

从单用例/进程开始，按证据增加到并发文件、独立 runner 进程、真实工作流并发量、共享主机任务。匹配当前配置、环境、构建模式和平台；不要靠随机负载或缩短生产期限制造另一种失败。

竞态在争用点加入 barrier；资源冲突证明同时获取同标识或证明原子唯一分配消除冲突。无法运行所需平台时报告达到的层级，使用远端证据；不能用其他平台通过替代。获准修复时每轮改一个怀疑所有者，保持归因清楚。

## 在所有者修复并结束

修正分配、就绪发布、全局状态或清理责任处，不在重试包装、快照归一化或宽超时处隐藏。稳定输入与真实资源分配解耦。

结束条件：原始特征有证据支持的分类；最小拓扑复现或明确外部证据与限制；授权修复在原失败/负例下失败、同拓扑修复后通过；所需恢复、并发和静止清理证据完整。远端 pending/skipped/failed 如实报告，不运行到偶然成功就称稳定。
