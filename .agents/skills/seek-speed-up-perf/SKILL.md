# 基于证据优化性能

## 先定义测量

确定用户操作、外部可观察的完成条件、工作负载范围、资源限制、允许的行为差异和停止条件。后端阶段与浏览器端到端分开测；排除网络或模型耗时时明确说明，不能称为完整产品延迟。以当前实际版本、实现和测试为准，旧 PR 描述及历史数字只作为线索。

调查实际路径，再按用户延迟、CPU、分配、保留内存、频率和置信度排序。每个候选必须有生产消费者、重复工作、复杂度假设及最小可证伪干预。大文件、可疑循环或缓存命中率本身不证明瓶颈。

## 建立测量卡

记录以下内容，再动生产实现：

- 操作与终点：计时起止、包含和排除的成本。
- 工作负载：独立成本维度、典型与尾部场景、固定分布及种子。字节、事件、请求、节点数不能互相替代。
- 入口：真实生产调用与构建产物、模拟的外部边界。不得复制算法做“基准实现”或只为测量增加公开接口。
- 状态：冷启动与热缓存、初始化是否计入、对象是否仍可达、GC 策略、保留内存与瞬时峰值。
- 判定：全部样本、聚合方式、重复次数、噪声估计、预算依据及负对照。
- 正确性：保持的输出、排序、错误、取消、并发和资源释放，以及允许的具体差异。

合成数据由固定常量生成，不依赖私人目录、真实提示、身份、凭证和线上服务。获准查看真实语料时只提取非识别性的聚合特征。冷样本用新进程及独立临时根；热样本明确保留什么。两侧必须完成相同验证并保留相同输出，解析后丢弃不能与完整验证及留存相比。

## 找到因果关系

先运行未优化版本，保存修订、命令、平台、输入、原始样本和结果。用剖析、分配、调用次数及阶段耗时缩小假设，一次改变一个因果因素，同时重测局部场景及端到端父路径。

可检查重复解析/复制、展开紧凑表示、无界中间状态、不必要的可写准备、隐藏视图计算、过宽订阅和重复扫描。所有权和信任边界的校验不能为速度删除；延迟计算要测首次激活；缓存或 singleflight 必须有失效条件、容量、独立等待者取消和释放所有者。

负对照应让原实现或受控恢复的昂贵路径触发新断言。预算既不能宽到放过目标退化，也不能低于噪声。不要挑最快一次、调环境变量绕预算或抬门槛掩盖退化。使用已有基准设施，避免另建校准体系。

## 浏览器与 CI 条件

涉及交互时使用真实浏览器输入并观察 UI 更新，包含最后一次停顿，区分定时器心跳与真实输入。说明首屏、滚动、分页、流式更新及隐藏后激活覆盖范围；假 DOM 和后端计算不能证明响应性。生产者要有界，避免补发突增改变负载。

计时任务避免与自己启动的重 CPU 工作争抢。CI 预算需在实际运行器重复测量校准；不能把一种运行时的速度系数直接用于浏览器、字节或无量纲比例。区分本地、历史和 CI 证据。

## 验收与停止

性能证据不能替代功能测试，不得静默截断数据、漏结果、改变错误时序或取消语义来达标。收益端到端消失、典型场景明显退化、内存无界或维护成本大于收益时拒绝方案。交付“负载 → 前后绝对值和比例 → 内存与终点语义 → 正确性及负对照 → 实际执行检查 → 未覆盖范围”，在约定范围停止。
