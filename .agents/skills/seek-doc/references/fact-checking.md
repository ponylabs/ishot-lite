# 事实核验：运行后再承诺

操作文档影响读者实际行为。命令、配置、默认值、错误提示及平台差异都属于需要证据的声明；阅读源码可以帮助设计验证，不能冒充精确操作已经成功执行。

## 建立最小证据链

对本次新增或改动的操作声明，检查“声明 → 事实来源 → 精确操作 → 观察结果 → 覆盖范围”。记录可以放在交付摘要，不要求每次创建永久验证报告。

1. 确认当前 checkout、任务基线、工作区差异和实际入口。核对清单、配置与入口形态，不从邻近模块复制安装命令或根据目录名猜技术栈。
2. 找到最强事实来源：配置/清单负责名称和入口，公开类型与接口说明负责调用契约，实现负责行为，测试负责实际覆盖路径，生成器负责派生清单，已接受决策负责取舍。
3. 在安全的临时数据或测试环境中，按文档将展示的原样命令、配置和顺序执行。记录退出码、实际产物、警告和失败，不仅记录“命令完成”。
4. 检查读者能否从给出的起点重复结果：当前 shell、工作目录、版本、依赖、权限、服务及样本前提是否写明。测试通过不能替代安装或构建入口的验证。
5. 涉及默认值时分别检查未提供配置与显式配置；涉及失败时实际建立对应失败条件；涉及多个平台或版本时逐项验证，不能扩大证据覆盖面。
6. 修改后重跑受影响操作和检查；生成器或事实源变化后重新生成派生物。旧页面与远端旧文字只用于识别变化，不作为事实终审。

## 不能执行与结果不符

| 情况 | 正确处理 | 禁止做法 |
| --- | --- | --- |
| 缺密钥、网络、数据库或平台 | 写明无法验证的具体声明、已检查证据、由谁在什么条件下补验 | 把“看起来正确”写成已验证 |
| 命令有删除、费用、发布或生产写入风险 | 先核实授权；选择已授权的隔离验证，否则暂停该动作并报告 | 为了文档核验擅自操作生产 |
| 操作结果与文案不符 | 区分实现缺陷、文档错误或环境差异，修正可证实的部分；争议处保留并报告 | 修改测试去迎合文案、吞掉失败 |
| 旧说明只在其他版本成立 | 明确版本适用范围或更新到当前状态；保留确有用途的升级记录 | 混用不同版本命令 |
| 只验证一个平台 | 明确只覆盖该平台，其他平台待验 | 宣称所有平台可用 |
| 用户只要求审阅 | 列出声明、位置、证据和缺口 | 未授权直接改文档或实现 |

无法复现的承诺不能继续作为已确认事实；也不能草率删掉已确认要求来掩盖实现问题。待验证内容使用准确状态和最小必要提醒，避免在正文各处堆重复免责声明。
