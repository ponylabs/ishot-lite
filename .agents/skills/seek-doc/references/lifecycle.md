# 文档生命周期与派生内容

这些规则按实际项目能力应用：没有站点、翻译或生成器的项目无需为它们创建目录或配置。

## 新增、修改与拆分

新增前确认读者问题和唯一主要归属。修改优先原位更新，不追加“本次修订”流水。拆分以职责和读者任务为依据：先确定接收页面及入口，再搬迁内容，留下足够的本地使用契约和精确链接，不能把重复改成两份继续维护。

## 移动与删除是一个完整变更

1. 移动前搜索文件路径、标题锚点、相对链接、参考式链接、Skill 入口、AGENTS 导航、代码字符串、构建清单及站点路由等消费者。
2. 确认新位置的归属和当前授权。一次迁移一个连贯主题，不能因为修改一页就顺手全仓搬家。
3. 同次修改源文件与已识别引用；更新相对路径、图片和锚点。已有公开路由需要保持别名或说明破坏性变化，不默默失效。
4. 检查旧位置不再存在第二个可编辑事实副本，搜索遗留路径，运行相关检查。链接检查器未覆盖的参考式链接或锚点须单独检查，不能靠绿灯推断完整。
5. 有生成站点或清单时重新生成并预览目标路径；报告移动/删除范围及不能核验的消费方。

## 当前事实、决策与临时记录

普通说明描述当前事实。提案明确尚未接受，历史决策、事故复盘及版本迁移保留其时间边界，不改写成当前事实。决策实施后删去过期计划清单，但保留独有理由、替代方案、已执行证据和覆盖缺口。Agent Notes 的状态、分类和格式以 [Notes 自身规范](../../../notes/README.md) 为准，归档操作使用 [seek-notes](../../seek-notes/SKILL.md)；implemented 的路径、名称等当前事实仍须同步，不能借“历史”免除更新。

只有确需跨会话移交且当前项目没有合适位置时才建立临时记录，标明负责人、待解决问题、失效条件及最终知识归属。结束后将成熟结论迁到事实拥有者，删除已解决讨论；不要把它变成另一份长期任务队列，也不强制每页附 Dev Note。归档资料是冻结历史，审计时默认排除；确需更正时在活跃事实拥有者建立后继说明，不改写已冻结正文。

## 生成内容

先查生成器、输入和全部消费者，再改拥有者并重新生成。不能只修一个快照、API 清单或网站产物使检查通过。验证生成流程的确定性与新鲜度，必要时用错误样本确认检查入口确能拒绝过期产物。生成器若只抽取首句，该片段也必须在输出位置表达完整的必要含义。

## 多语言（存在时）

先读取项目语言策略：哪一份可编辑、如何配对、如何记录同步状态，以项目实际流程为准，不默认英语永远权威。同步本次受影响语义、术语、链接、示例与版本限制；结构检查不能证明翻译准确。只有现有解析器明确要求时才保留物理行数对齐，不为通用模板引入此要求。

专门翻译工作流若只允许用户显式调用，不因普通文档编辑自动启动。无法同步时说明具体缺口和责任，不假装所有语言已更新。

## 文档站与发布（存在时）

仓库源文档与站点应有明确单向来源；生成树、缓存和构建产物不是第二份可编辑源。已发布页面改源，新页更新允许发布的清单，移动或删除同时更新路由、导航和入链。新增公开内容前核对现有发布范围，不把内部复盘、运行手册或 Agent 规则默认公开。

修改清单前读取其当前类型和导航配置，复用已有分区、顺序与语言模型；字段和映射规则不凭记忆填写。区分来源别名与公开路由别名，两者不一定等价。未发布目标、外部链接、页内锚点及资源图片分别检查；图片复制也会公开内容，必须处于许可发布范围且为仓库内合法资源。不要为满足站点而把专属路由硬写进通用源文档。

同时验证仓库链接与渲染后的路由、标题锚点、图片。源文件存在不代表站点链接有效。先运行项目真实预览/构建检查；内容进入构建不等于已部署。新增域名、权限、托管或发布操作须有对应授权。


## 历史格式与兼容记录（存在持久化协议时）

先区分三种证据，不能混为一种文档：当前格式变更的兼容决策、已发布版本的事后观察、某个历史检查点的完整格式参考。事后重建不是当时的兼容批准；历史参考不能替代当前写入格式目录。

- 固定来源 tag、提交或确切 PR 树；中间提交不等于最终合并，更不等于产品发布。历史路径链接到固定来源，不伪造当前行号。保留真实类型、可选字段和不透明声明，并单独记录实际版本常量。
- 兼容说明分别回答旧读者如何读取或安全拒绝新数据、新读者如何保留旧数据含义，以及缺少新特性时的旧行为；升版链接迁移及验证责任。结构差异本身不证明必须升版，更不证明同版安全；字段不变但默认错误策略、顺序或含义改变也需要核对。用真实旧/新版本与样本分别验证两个读写方向，将“可读且保留含义”“明确安全拒绝”“尚未验证”分开说明，不以新读旧成功概括为“无需迁移”或“完全兼容”。
- 已接受或被后续记录依赖的证据通过后继记录更正，不重写基线。未接受的末端记录只有在现有工具明确支持且授权时才更新，并重新评估完整变化。
- 若项目生成 schema、摘要或差异区域，保留可追溯的机器来源和校验结果，人工解释放在生成区域之外。校验器只能核验已有证据，不能创造历史来源、证明运行时解码接纳或迁移安全。
- 保留无变化版本与缺失来源的边界；按真实版本顺序比较，不把事后档案插入当前变更批准链。具体 schema 字段、散列、目录名和工具由项目格式拥有者决定，本模板不预建虚构协议。
