# 写清 PR 的变化与证据

先读实际差异和仓库已有 PR 模板。依赖栈中的每个 PR 只描述相对自己 base 的变化。说明跟随当前代码更新，不保留已撤销方案的承诺；创建 PR、更新远程说明及上传附件仍需对应授权。

## 默认内容

沿用上游的四个二级标题：`Motivation`、`Changes`、`Testing`、`AI Usage`，内容默认中文；目标项目已有明确格式时遵从该格式并说明差异。AI Usage 如实说明人与 Agent 在拆解、设计、测试、实现、评审处理中的分工，不把执行检查或允许推送冒充人工代码审查。DeepSeek 的强制同仓 Issue、参与度百分比与 AI-DECLARATION 徽章属于其协作政策，通用模板不默认强制采用；项目采用时按其完整政策执行，不编造缺失记录。

- 动机：一句话说明问题。存在关联 Issue 时按真实关系引用，解决才用关闭语义；不能为满足格式虚构 Issue。
- 变更：分别说明接口和行为。接口包括命令、配置、环境变量、公开导出、协议及持久化格式；行为包括结果、默认值、性能、时序和输出。README、AGENTS 和 Skill 也是对读者的行为变化。无变化就明确无，不靠大量细节掩盖边界。
- 验证：先说明验收设计，再列实际运行的命令或步骤、结果和证据来源。未运行、失败、环境受限分开写；计划不是已执行证据。
- AI Usage：只记录已发生的分工；未处理评审时明确尚无评审处理，不猜测人工贡献。

## 按变更类型组织证据

行为改动给出场景、前后行为与对应测试；性能给出测量条件、次数、取值方式和前后数字；不改行为的重构给出未变快照、旧新对照或等价性证明；文档给出事实、链接、示例和适用时的翻译检查。混合改动分别覆盖，不用一个“全部通过”替代设计。

修改原测试表达的业务行为时说明理由；提高已存在预算时说明旧值、新值及必要性，不能为绿灯放宽。GUI 演示应标明示范提交和环境；缺少应有证据时说明限制。兼容性和升级步骤必须与实际差异一致。

## 维护而非追加

更新前读取当前远程正文，保留人工写入的说明和媒体，只修改失真的相关部分。角色披露只陈述已知的人与 Agent 决策/执行分工，不能把授权推送当作人工代码审查，不能编造已处理评审。

远程写入后读回，确认小节完整、事实与当前 head 一致、旧声明未重复、附件引用可用。若远程正文或 head 在操作期间变化，先比较合并，不覆盖他人新内容。
