# 响应式界面

视觉检查按 [界面 Skill](../seek-ui/SKILL.md) 选择影响范围；在整个页面或弹窗中比较换行与布局关系，保留草稿、焦点和操作可达性。示例不限定覆盖范围，放进视口不是唯一验收标准。

## 视口与空间决策

从项目实际支持范围确定最小视口，不直接继承 DeepSeek 的 390 CSS px。约定范围内不得出现意外重叠、裁切、整页横向滚动或不可达的主要操作。

先调整空间分配或换行，再考虑截断、图标化或移入更多菜单。主要状态与操作不能消失；不以全局裁切、统一缩小字体或点击区域掩盖冲突。字体缩小必须有具体设计依据。

## 文字与标题

截断内容必须能在其他页面或打开菜单后完整获取。错误和其他无法从别处读取的重要信息不截断。导航、选择器、按钮、标签优先单行截断，但不能牺牲识别对象和执行动作所需信息。

页面标题优先完整显示，必要时操作区另起一行。卡片标题自然换行；若限制行数，保留完整标题的读取方式。

## 图标化与悬停

只有语义清楚或用户熟悉的操作才可简化为图标；可悬停时补充动作名称提示，并始终保留可访问名称。低频且模糊的导航不能仅因空间不足就移除文字。

悬停能力与视口宽度分别判断。CSS 使用 hover 能力查询；JavaScript 在混合输入设备上判断当前指针事件，忽略 touch 的悬停模拟。手机点击不能留下仅用于悬停的背景或按钮显隐。无悬停设备仍能通过明确控件访问操作，键盘也能到达同一能力。

选中、展开、启用、按下和焦点状态独立于悬停能力。不能靠清除焦点修复粘滞悬停，触摸聚焦的文本框也可能需要焦点样式。

## 宽度、提示与键盘

控件仍可见和可交互时，宽度变化应保留焦点，不为切换布局重新挂载。确实隐藏或移除时转移到合理目标，不无故唤起移动键盘。

只解释动作名称或快捷键的辅助 tooltip，在移动端可省略，点击仍直接执行动作；包含实质补充说明的提示必须支持点击查看。移动端不自动打开键盘，除非产品明确要求。

优先使用 CSS 能力检测：pointer 描述主要指针精度，hover 描述主要指针悬停能力，宽度查询负责布局断点。这些都不能检测实体键盘；禁止解析 UA 决定布局。iOS Safari 聚焦缩放问题按目标平台实际验证并局部处理，不将 DeepSeek 的 16px 规则无条件推广给所有设备。
