# Agent Notes

Agent Note 保存代码、测试和当前文档不能充分解释的长期提案与决策：为什么这样选择，以及放弃了什么。本页拥有记录位置、创建条件、格式和生命周期规则；操作方法见 [seek-notes](../skills/seek-notes/SKILL.md)。

## 位置与分类

路径为 `{状态}/{类别}/yyyy-mm-dd-topic-title.md`。日期为首次提出日期，移动和更新时保留；主题用英文小写 kebab-case，正文中文。

- proposed：尚未实现或部分实现的提案。
- implemented：已经交付的决定；实现事实变化时同次更新，见 [局部规则](implemented/AGENTS.md)。
- rejected：考虑过但拒绝的提案，只在仍能防止有吸引力的实际错误时保留。
- archived：单独的已实现历史目录，不是活跃状态；见 [冻结规则](archived/AGENTS.md)。

类别封闭为 feature（新能力）、bug-fix（修复缺陷）、simplification（移除复杂度）、architecture（已交付源码结构）、process（围绕代码的工具和流程）、testing（测试基础与策略）。新增类别必须同时更新本页与检查器。不要创建含混的 refactor 类。

按实际需要创建状态/类别目录，不预建全部组合。直接浏览或搜索目录，不创建集中 INDEX.md，不使用旧位置 docs/rfc 或 docs/rfcs。记录间使用相对 Markdown 链接，不使用裸编号。

## 何时记录

只有代码、测试和已有文档无法解释的重要长期理由才需要新增或更新记录。更新已有决策拥有者即可，不为局部 UI 或机械修改生成流水。新记录必须按 [局部入口](AGENTS.md) 检查取代关系。

部分取代保留两篇并互链，更新仍有效事实。完整合并后，只有新拥有者保留全部独有理由、替代、后果、必要验证和已知覆盖缺口，且修复所有入链，才可按授权删除旧记录；不能让 Git 历史成为理由的唯一副本。

功能移除只有在生产实现、配置、schema、持久化/传输格式、迁移和兼容路径均不再保留该能力，当前文档和支持性测试也不再把它当作可用功能时，才算完整取代。新记录需保留原动机、移除理由、替代方案、放弃的能力、重新引入条件及完整移除证据。删除一个入口或默认值只是部分取代。

## 文件格式

活跃记录前四行固定为标题、空行、状态、空行：

```markdown
# Agent Note: 中文主题

Status: proposed

```

状态必须匹配目录：`Status: proposed`、`Status: implemented`，或 `Status: rejected — 一句话原因`。状态不附带日期或括号，全篇只能有一条状态行。

正文第一个二级标题是 `## 问题`。统一中文标题如下，允许在必要章节间增加具体技术章节：

- proposed：问题、提案、考虑过的替代方案、验收条件、风险。
- implemented：问题、决策、考虑过的替代方案、后果。不得保留“提案”“计划”“迁移计划”“验收条件”等提案期二级标题；已验证行为可放“测试”或“验证”。
- rejected：保留提案期正文，至少包含问题、提案、考虑过的替代方案；拒绝理由放状态行，不改写成已经实施。

问题应脱离解法也成立；替代方案必须真实，不得为满足章节而编造。此模板无上游旧记录，因此不引入 DeepSeek 特定历史日期的格式豁免。

proposed 移到 implemented 时，同次更改状态和章节，将计划改成已交付事实；验收条件和风险归入后果或当前验证。proposed 移到 rejected 时只更改状态并保留正文。移动记录时修复活跃入链。

## 归档与删除

按未来决策价值判断，不按年龄、字数或数量配额。仅描述小型 UI 调整或纯机械变更的记录可按授权删除；局部缺陷、性能改进和行为决策不能因实现小就删除。仍解释所有权、安全、兼容、持久语义、负向保证或重引入条件的记录保持活跃。

已完成、理由不再指导未来但仍有历史价值的 implemented 记录移至 `archived/{类别}/原文件名`。保留 `Status: implemented`，在其下一行插入 `Archived: YYYY-MM-DD`，不修改正文、格式或历史出链。归档日期不得早于首次提出日期。proposed 不归档，过时提案应拒绝。

归档文件由 `archived/manifest.json` 记录 SHA-256 封存值，采用上游只追加新封存的方式；此模板是单语言文件，不要求英文/中文/sidecar 三件套。封存后不得编辑、移动或删除，不作为当前行为权威。活跃入链须有效，归档出链保留历史语境，不追着现状修复。

## 检查范围

`python3 scripts/check_harness.py` 验证路径、真实日期、活跃状态和中文章节、旧路径禁用、归档元数据与冻结哈希。`--seal-archives` 只追加新归档封存，先验证已有封存与基准未改变。检查器不判断理由、替代方案、事实或取代关系是否语义正确，内容审查仍不可省略。
