# 应用受控测试

实际测试选择、编译参数和链接依赖由上一级 test.py 拥有。本目录与各 Sources 模块下的 tests 分工验证应用协调、图像、快捷键、资源和模块边界；不要从文件存在推断某个测试已被执行。

MainAppValidation 以受控偏好和通知拦截加载 AppKit 资源，检查 nib 自定义类、outlet、action 及 Lite 界面约束；按源码条件绕开可能改变音量的设备路径。它不运行完整主循环或证明设备采集成功。

MainWorkflowValidation 使用真实 AnnotatedImageController、画布和资源，注入合成白色图像及鼠标动作，执行方框绘制、撤销/重做和 PNG 导出；导出调用底层渲染方法，不执行会采集屏幕的保存按钮。另验证录屏选区视图依赖和几何更新。输出尺寸与像素数取决于环境，只读当次报告，不保存一次运行的 PASS 作为当前事实。

ApplicationFunctionTests 只覆盖临时目录重名与 JSON 等受控行为，不运行登录项、辅助进程、重启或设备授权。默认框架测试验证当前实现的行为断言。显式历史差分模式才从指定外部档案加载原二进制作限定范围参照，不等于主程序全路径等价。helper 测试的进程和通知防护由[本地测试说明](../Sources/iShotHelper/tests/README.md)拥有。

模块行为测试也由默认 runner 编译并执行：覆盖录制控件状态与清理、合成采样时间戳、事件和滚动几何、偏好控件、贴图缩放与菜单，以及依赖的几何、所有权和权限界面布局。测试中的替身只用于避免设备、权限和外部动作，不能据此声称真实采集通过。录制格式和贴图配置使用进程内临时 defaults，不写用户偏好；贴图初始化等待可观察的图像就绪并有超时。推广目录已从 Lite 界面退役，不再维护其旧数量和广告顺序断言，入口不可达由 MainAppValidation 验证。

运行和结果新鲜度规则见[测试说明](../../docs/testing.md)。新增测试必须接入实际 runner，并让失败真实退出；硬件、安装和权限验收不能用测试替身通过来替代。
