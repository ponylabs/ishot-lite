# 文档约定

本文件拥有人类可读文档的类型、固定名称、创建条件与职责边界；Agent Notes 格式由其自身规范拥有。维护方法见 [seek-doc](../.agents/skills/seek-doc/SKILL.md)，表达判断见 [seek-prose](../.agents/skills/seek-prose/SKILL.md)。不在 Skill 中维护另一套目录规范。

## 固定入口

所有派生项目保留六个入口，以真实事实更新，不用空问卷代替内容。

| 文件 | 唯一主要职责 |
| --- | --- |
| `README.md` | 项目用途、状态、最短使用入口和深入导航 |
| `AGENTS.md` | 全局开发约束、按任务读取的 Skill 路由 |
| `docs/AGENTS.md` | 本文档结构、命名、职责和生命周期约定 |
| `docs/architecture.md` | 当前模块边界、依赖、状态与数据流、关键取舍入口 |
| `docs/development.md` | 实际环境、开发入口、修改与交付流程 |
| `docs/testing.md` | 真实检查命令、覆盖边界、失败诊断和未验证范围 |

README 链接事实拥有者，不能手工复制全部操作与验证细节。固定入口不是固定业务架构：不预设 `src/`、`packages/`、语言、数据库或部署方式。

## 按场景建立

下列名称与位置固定，只有真实内容出现才创建；本文中的路径名不是已经存在的文件链接。

| 路径 | 创建条件与职责 |
| --- | --- |
| `docs/glossary.md` | 跨模块术语有歧义；定义领域含义，不堆普通技术名词 |
| `docs/subsystems/README.md`、`docs/subsystems/<主题>.md` | 架构总览不足以解释独立子系统；索引仅导航，主题页说明当前机制 |
| `<模块>/README.md` | 模块已有独立职责或调用者；记录使用契约、失败、限制、实现入口 |
| `<子树>/AGENTS.md` | 有相对父层新增的长期局部约束；不复制父层规则 |
| `docs/cookbook/<主题>.md` | 可重复操作需要前提、步骤、结果与失败恢复 |
| `docs/defensive-patterns/<主题>.md` | 项目需要在审查中执行的防错规则；记录适用对象、反例和验证 |
| `docs/postmortem/NNNN-<主题>.md` | 真实事故按四位递增编号命名，需要时间边界、原因、影响、补救和预防证据 |
| `.agents/notes/<状态>/<类别>/yyyy-mm-dd-<主题>.md` | 非平凡选择需要保存理由、替代与后果；格式、状态和生命周期见 [Notes 规范](../.agents/notes/README.md)，归档操作由 seek-notes 执行 |
| `docs/web-styling.md` | 项目涉及 Web；记录实际样式系统、布局、字体、颜色、间距、组件复用、主题与响应式约定 |
| `docs/ui-radius.md` | 项目涉及 Web 且需统一组件形状；记录半径 token、使用映射、嵌套关系和经确认的例外 |
| `docs/upgrade-guide/v<版本>/<条目>/guide.md` | 有对外破坏性变化；版本表示从该版本升级，按条目记录影响、旧新行为和已验证迁移步骤，不建立根 README |
| `docs/user/<主题>.md` | 面向终端用户的使用说明需要独立于开发文档；建立入口 `docs/user/index.md` |

主题采用稳定的英文小写 kebab-case，正文、标题、说明默认中文；代码标识、协议与命令保持原样。模块目录跟随真实代码布局，不为文档创建虚构模块。条件目录首次产生多篇内容时可加 `README.md` 导航，但升级指南保留其版本/条目树，不建立根 README；Notes 不建立全局 `INDEX.md`，按状态/类别及必要的直接链接检索。

## 演进与规模

优先原位修订最近的事实拥有者，删除失效内容而不是附加“新版说明”。每个新增文件回答一个独立读者问题；只有独立职责、更新节奏或引用需要才拆分。父层只导航，下层承载细节。不得为凑齐目录预建空页面、复制教程或按每次任务追加日志。

当前事实与历史决策分开。长文先检查重复、过期内容和错误归属，不按硬字数删掉失败/安全约束。移动文件同次修复活跃入链；归档正文冻结，不追着当前实现修旧历史。结构扩展确有必要时先说明现有类型为何不足，再修改本契约及对应检查，不能悄悄并存同义目录。

## 表达与检查

每段正文占一个物理行，使用编辑器软换行；代码块、表格和列表保留结构。普通文档描述当前事实；历史原因放提交、PR、Notes 或事故复盘，不在现状文档保存实施过程。测试机制和夹具放在最低事实拥有层，上层只链接；架构页说明测试责任与边界，不手工枚举测试文件、用例数或执行状态。精确的测试、包、命令及字段清单由源码、项目配置或生成器拥有，不在多篇文档维护副本。

长文先迁移归属错误的内容，再精简冗余；必要契约不应为了缩短篇幅而删除。上游按英文词数的预算不能直接当作中文上限，通用检查目前未启用字符预算检查，内容规模通过审查把关。需要预算时先明确读者、计量方式和充分空间，再接入真实检查，不能声称已有自动保证。
